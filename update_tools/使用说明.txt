智能文档系统 —— 自动更新说明（2026-11-21）

一、两个角色
  开发机：写代码的那台，可以关机、可以带走。
  部署机：常开的那台，路径 D:\智能文件系统。

二、开发机：改完代码，双击「发布更新.bat」
  1. 构建前端，打包 update.zip
  2. 推到 GitHub 仓库的 releases 分支（不碰 master）
  3. 推不上去会自动改走 GitHub API；两条路都失败才报错

三、部署机：双击「同步更新.bat」，或建计划任务每 10 分钟跑一次
  流程：
    取 version.json（先直连，再走镜像）
    -> 版本比本地新才下载
    -> 校验大小 + SHA256 + 包内版本号，三道全过才装
    -> 停服务 / 备份 / 覆盖 / 依赖有变化才 pip / 重启 / 健康检查
    -> 任何一步失败自动回滚并重启旧版本
  更新工具本身也在包里，下一轮自动生效；update_config.json 不会被覆盖。

四、日志：D:\智能文件系统\data\update.log
  up to date (版本)                已是最新，没做事
  package verified from ...        包校验通过，开始安装
  size mismatch / sha256 mismatch  拿到的是旧缓存，已换源重试，本轮跳过
  no usable package this round     所有源都拿不到正确包，等下一轮，不影响正在跑的服务
  health check OK                  安装完成，服务正常

五、文档显示「不识别」怎么处理
  打开服务 -> 设置 -> 文件关联（重定位）
  搜索目录留空 -> 点重定位
  留空会同时扫描 data\documents 和 data\inbox，一般能全部找回；
  找回后路径写成绝对路径，之后不会再因为换目录而失效。

六、文件夹大小为什么比开发机小（这是正常的）
  迁移包有意不包含：
    data\logs            约 1.7 MB   运行日志，会重新生成
    data\recycle_bin     约 96 个文件 回收站
    data\temp            临时文件
    frontend\node_modules 数百 MB    只有开发机需要
  必须完整的三项（对得上就说明数据没丢）：
    data\documents       4 个文件，约 8.5 MB
    data\inbox           14 个文件，约 3.4 MB
    data\database\app.db 约 1 MB

七、一次性安装本工具（仅这一次）
  解压后双击「安装更新工具.bat」，它会自动找到部署目录并把工具覆盖进去，
  然后问你"现在立即检查并安装最新版本"，回车即可。
