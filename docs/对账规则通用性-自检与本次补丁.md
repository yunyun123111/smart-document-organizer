# 对账规则通用性：自检结论与本次补丁

日期：2026-11-13
定位：对账是**功能**，规则要对任意业务线、任意单据组合成立；现有真实资料只作回归样例，不构成规则依据。

## 一、本次修掉的 4 个通用缺口

| # | 缺口 | 表现（任意业务线都会遇到） | 修法 |
|---|---|---|---|
| 1 | 利息静默 | 上下游结算有差额，但台账应收/实收两条利息都没登记时，规则原本一个字都不报，差额被吞掉 | 新增分支：差 ≠ 0 且两侧利息均空 → WARNING「上下游结算存在差额，台账未登记利息」 |
| 2 | 少开票按错误算 | 发票合计 < 结算金额（分批开票、跨月开票的常态）被判 CRITICAL | 金额差异按方向分级：**少于应有金额** → WARNING（附「可能尚未开完全部发票」）；**多于** → CRITICAL |
| 3 | 缺件一刀切 CRITICAL | 业务尚未开始的业务线、只缺凭证的业务线，缺件也被判错误 | 新增 `_missing_severity`：付款回单属凭证 → 永远 WARNING；结算/发票看台账该方向是否已登记金额，有 → CRITICAL，无 → WARNING |
| 4 | 规则常量前后倒置 | `_CHECKED_CELLS` 用字面量 "up"/"down"，方向常量定义在其后，改值会不一致 | 方向常量前移，核对格改用 `DIRECTION_UP/DIRECTION_DOWN` |

判定原则一句话：**金额对不上是错误，单据没到是进度。**

## 二、明确仍是「台账模板约定」的部分（不是通用规则，改模板需同步）

- sheet 名：`云创总合同`（主表）、`结算数据`、`宏达收付款台账新`；主表以外的 sheet 只做金额补充。
- 列位置：`2.0编号` 在表中出现两次，按“锚点列右侧最近一个”定位。
- 编号体系：采购前缀 `HSYCCG / SJWLCG / BOTC / CG`，销售前缀 `HSYCXS / SJWLS / SOTC / XS`；两套体系并存视为同一业务线。
- 角色关键词：结算 / 发票 / 货权 / 回单/收付款凭证 / 合同，用于单据归类；新单据类型需扩词表。
- 方向判定：合同号前缀 → 公司主体（云创/陕建）→ 货权正文判向。

这些属于“台账与资料的组织约定”，不是某条业务线的事实，因此保留在常量里；换模板时改常量即可，不动规则。

## 三、通用性回归测试（`backend/tests/test_reconciliation_generality.py`）

全部用合成业务线与合成单据，不读取真实台账，覆盖：

1. 上下游齐全 + 利息已登记 → 零差异
2. 两张不同日期的发票分批开票、合计等于结算 → 不判重复、不出差异
3. 发票低于结算 → WARNING
4. 发票高于结算 → CRITICAL
5. 结算单高于台账 → CRITICAL
6. 上下游结算有差额、台账未登记利息 → WARNING
7. 差额与台账应收利息一致 → 无差异
8. 台账金额全空（业务未结算）→ 5 个缺件全 WARNING
9. 台账已登记结算、结算单缺失 → CRITICAL
10. 有付款额无货款回单 → 缺件 WARNING + 待补说明
11. 结算单归档但金额未识别 → 「金额未识别」而非「缺件」，矩阵计 1 份
