# 方案：业务线台账自动对账

> 目标：合同/结算单/发票/出库单/收付款回单识别归档后，自动与手工台账比对，按**业务线**给出差异结论——哪条业务线、缺什么、金额差多少、上下游是否勾得上。
>
> 状态：口径已按实际台账核对，待确认后开工。

---

## 一、业务模型（按你的规则固化）

一条**业务线**（`business_no`，如 `YWX202602120005`）是一次完整购销闭环：

```
上游（采购）                          下游（销售）
├─ 采购合同 M列/HSYCCG…   ── 货权 ──>  ├─ 销售合同 K列/HSYCXS…
├─ 上游结算单（采购结算）  ── 利息 ──>  ├─ 下游结算单（销售结算）
├─ 上游发票                            ├─ 下游发票
├─ 出库单/货权转移（上游）              ├─ 出库单/货权转移（下游）
└─ 付款回单                            └─ 收款回单
```

两条硬规则：

1. **单侧两两核对**：上游「结算 ↔ 发票 ↔ 付款回单」金额一致；下游「结算 ↔ 发票 ↔ 收款回单」一致。
2. **跨端利息勾稽**：`下游结算金额 − 上游结算金额 = 应收利息`（实测允许等于 R 或 S 任一；R≠S 时提示"利息尚未收全"）。

单据矩阵固定 **2 方向 × 5 类 = 10 格**，每格都必须有，**未结完款不豁免**（你的口径）。

## 四、数据模型改动（最小侵入）

### 4.1 新增对账结果表（SCHEMA_VERSION 6）

不动 `business_records` / `business_files` 结构（保护已有 8 份档案）：

```sql
CREATE TABLE IF NOT EXISTS reconciliation_reports (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    business_no VARCHAR(255) NOT NULL,            -- 业务线号（主键维度）
    ledger_sheet VARCHAR(64) NOT NULL DEFAULT '', -- 来源 sheet：云创总合同（对账固定取此表）
    up_contract_no VARCHAR(255) NOT NULL DEFAULT '',
    down_contract_no VARCHAR(255) NOT NULL DEFAULT '',
    up_settlement NUMERIC(18,2) NOT NULL DEFAULT 0,   -- 结算数据 M 合计
    down_settlement NUMERIC(18,2) NOT NULL DEFAULT 0, -- 结算数据 P
    interest_receivable NUMERIC(18,2) NOT NULL DEFAULT 0, -- 宏达 R 应收利息
    interest_received NUMERIC(18,2) NOT NULL DEFAULT 0,   -- 宏达 S 实收利息
    status VARCHAR(16) NOT NULL DEFAULT 'ok',      -- ok / warning / error
    diff_count INTEGER NOT NULL DEFAULT 0,
    report_json TEXT NOT NULL DEFAULT '{}',
    checked_at DATETIME NOT NULL,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS ux_reconciliation_business_no
    ON reconciliation_reports (business_no);
```

`business_no` 全局唯一即可（两套编号的 YWX… 实际不重复；若重复则加 `ledger_sheet` 复合键，实施时校验）。

## 五、核对规则（7 条）

金额容差 `0.01` 元；同一方向同一角色多张单据按**求和**比对。

| 编号 | 规则 | 取数来源 | 判定 | 差异类型 | 级别 |
|---|---|---|---|---|---|
| **R1** | 单据齐套 | 10 格矩阵 | 某格无关联文档 | `MISSING_DOC` | 缺合同/结算/发票 CRITICAL；缺货权/回单 CRITICAL（按你口径不豁免） |
| **R2** | 上游单据一致 | 结算 M 采购结算合计 ↔ 上游发票价税合计 ↔ 上游**回单文档**合计 | 回单合计与台账登记额取差 | `AMOUNT_MISMATCH` | 回单超额 CRITICAL；回单未覆盖 WARNING |
| **R3** | 下游单据一致 | 结算 P 销售结算合计 ↔ 下游发票价税合计 ↔ 下游**回单文档**合计 | 同上 | `AMOUNT_MISMATCH` | 同上 |
| **R4** | 跨端利息 | `P − M` ↔ 宏达 **R 应收利息** 或 **S 实收利息**（任一命中即通过） | 两者都不等且差 > 容差 | `INTEREST_MISMATCH` | CRITICAL（R≠S 时为 INFO） |
| **R5** | 合同归属 | 单据上 `contract_no` ∈ {M, K}（含 2.0 编号 N/L 兜底） | 不在集合内 | `CHAIN_BREAK` | WARNING |
| **R6** | 日期时序 | 合同日期 ≤ 结算日期 ≤ 开票日期；收付款日期 ≥ 合同日期 | 倒置 | `DATE_CONFLICT` | WARNING |
| **R7** | 编号唯一 | 业务线内发票号重复；同一文档挂两条业务线 | 重复 | `DUPLICATE_BIZ` | WARNING |

**R1 必须区分「真缺」与「有但没归集」**：按业务线号 / K / M 在文档库搜一遍，搜到未关联 → `MISSING_DOC` 附 `candidate_document_ids`（前端给「一键关联」），搜不到才是真缺。

**台账本身缺失**：结算数据或收付款表里找不到该业务线对应行 → `LEDGER_MISSING`（WARNING，提示台账登记不全，不中断其余规则）。

**台账内部差额降级（实测修正）**：台账里的「支付金额 / 回款金额」是按**合同价**付的，「结算金额」是按**实际吨位**结的，两者天然有尾差（实测 114 条误报全部来源于此）。因此「付款 vs 采购结算」「回款 vs 销售结算」只出 INFO（标题分别为「上游付款金额与采购结算金额存在差额（预付/尾款）」「下游回款金额与销售结算金额存在差额（尚未回全）」），**不再判 CRITICAL**。CRITICAL 只保留给「回单文档合计 vs 台账登记额」不一致这一种真差错。

**利息基准（实测修正）**：58 条有结算的业务线中，`下游结算 − 上游结算` 等于 R（应收）45 条、等于 S（实收）37 条，**无一条两者都不等**——存在「应收已登记、尚未收全」的正常状态。所以 R4 判定为「R 或 S 任一命中即勾稽通过」；R≠S 时输出 INFO「应收利息与实收利息存在差额（利息尚未收全）」。只比 R 会在实测台账上误报 13 条。

## 六、计算流程

```
1. 读台账（4 sheet，按 ExcelSheetConfig 的 column_map）
   主表（云创总合同，唯一对账来源）：业务线行 → business_no, K, M, H, S, 船名, 对手方
   辅助（物流合同）：只把 SJWL 合同号并入同名业务线的编号列表，不加行、不加金额
   结算数据：按 F 关联 → up_settlement(M 合计), down_settlement(P)
   收付款：按 B 关联 → interest_receivable(R), interest_received(S), pay(K), receipt(O)

2. 按业务线聚合文档
   a. M / K 查 business_records → business_files → documents
   b. 业务线号直接在 documents/document_fields 检索
   c. 每份文档归位 (direction, role)，规则见 4.3
   d. 金额取 document_fields["amount"]；取不到标 UNPARSED_AMOUNT（不按 0 误算）

3. 跑 R1–R7 → diffs
4. upsert reconciliation_reports（按 business_no）
5. 有对应档案的，同步写 doseier_anomalies（可选，异常中心统一）
6. 返回汇总：业务线数 / ok / warning / error / 未归属文档数
```

**触发**：手动「一键对账」（可全量/单条）；归集成功后异步增量（不阻塞上传）；定时不默认开。

**性能**：75+29 条业务线 × ~20 文档，全量 < 1 秒。

## 十二、已确认口径

| 项 | 结论 |
|---|---|
| 主键 | 业务线号（主表 O 列） |
| 利息 | 第 4 个 sheet「宏达收付款台账新」**R 列 应收利息**为主，**S 列 实收利息**作为等价命中条件（任一勾稽上即通过） |
| 上下游合同 | 「云创总合同」K 列 销售合同编号OA（下游）、M 列 采购合同编号（上游）；「物流合同」不参与对账，仅把其 SJWL 编号并入同名业务线的编号列表供文档归位 |
| 对账主数据 | **只用「云创总合同」**（用户指示：物流合同只是为统计陕建线业务而另记一套） |
| 缺件豁免 | 不豁免，10 格都必须有 |
