# 「目录自动监控 + 盖章检测」实施方案

> 版本：v1 草案（待确认）
> 项目：智能文档自动整理系统（smart-document-organizer）
> 原则：增量开发，复用现有 pipeline，不重写、不破坏老数据，尽量零新增依赖



***

## 一、目标



1. **目录自动监控（主动式）**：用户可设置**一个或多个监控目录**，系统后台定时扫描，发现新文件**自动触发现有整理流程**（识别 → 重命名 → 归档），无需人工 "放入待整理目录再点开始"。

2. **盖章检测（主动标注）**：文件进入系统时，自动检测文档**是否已盖章、有几个章**，结果作为字段保存并在界面上标注（供业务校验 "合同 / 发票是否已盖章生效"）。

两者独立可开关，互不依赖。

## 三、功能 A：目录自动监控

### 3.1 使用场景



* 用户把文件放进 "桌面 / 下载 / 指定共享文件夹" 等任意目录，系统自动收走整理，无需打开网页。

* 可配合手机 / 同事投递（局域网共享目录），实现 "丢进去就不用管"。

### 3.2 新增配置项（config.py + .env）



| 配置                    | 默认            | 说明           |
| --------------------- | ------------- | ------------ |
| `WATCH_ENABLED`       | `false`       | 总开关          |
| `WATCH_DIRS`          | `[]`（空 = 未设置） | **监控目录列表**（支持多个，.env 存 JSON 数组） |
| `WATCH_INTERVAL`      | `30`（秒）       | 扫描间隔（所有目录统一） |
| `SEAL_DETECT_ENABLED` | `true`        | 盖章检测开关（功能 B） |

### 3.3 新服务：`backend/services/folder_watcher.py`

完全复用 `email_ingest.py` 的线程模式，**多目录**：



```
scan\_loop(interval, stop\_event)

&#x20;  └─ 每 interval 秒，对每个监控目录 watch\_dir：

&#x20;       1\. 扫描 watch\_dir（不存在/不可写 → 记录该目录状态错误，跳过本轮）

&#x20;       2\. 过滤：仅文件、非隐藏（.xxx / \~\$xxx）、类型已知（get\_file\_type != unknown）

&#x20;       3\. 快照比对：记录 (path, size, mtime)，与上次快照对比

&#x20;          → 存在【新增/变化】文件 且 无运行中任务（processing\_service.\_has\_running()）

&#x20;          → 调用 processing\_service.start\_job(watch\_dir)

&#x20;       4\. 更新该目录状态：最后扫描时间 / 发现文件数 / 最近触发任务号 / 最近错误
```

**关键设计决策：直接&#x20;**`start_job(watch_dir)`**，不做文件搬运**。理由：



1. `start_job(source_dir)` 原生支持任意源目录，归档时 `archive_service` 会把文件自动移走；

2. 剩余在监控目录里的 "待人工审核 / 重复 / 失败" 文件，下次扫描会被现有 `status + hash 双命中跳过` 逻辑忽略（processing\_service 已实现），不会重复消耗 OCR/AI；

3. 监控线程只负责 "发现有新文件 → 触发任务"，与整理 pipeline 解耦，文件安全（不移动、不删除用户目录里的东西，归档动作仍走现有 ArchiveService）。

**防冲突 / 防循环规则**：



* 监控目录 = 回收站 / 归档目录 → 启动时拒绝并提示（防止把已归档文件当新文件反复扫描）；

* 已有运行中任务时不触发新 job（复用 `_has_running`）；

* 监控目录被删除 / 无权限 → 状态栏显示错误，不崩溃、不自动停用（用户改好目录即恢复）。

### 3.4 生命周期与 API



* 启动：`main.py` 的 `lifespan` 中调用 `folder_watcher.sync_from_settings()`（与邮箱轮询并列）；

* 配置变更：`PUT /api/settings` 保存后，检测到 watch 相关字段变化 → 动态重启线程（照抄 email 的同步逻辑）；

* 状态查询：新增 `GET /api/system/watch-status`，返回 `{ enabled, running, interval, dirs: [{ dir, last_scan_at, found_files, last_job_id, last_error }...] }`，前端设置页轮询展示。

### 3.5 前端（SettingsView.vue 新卡片「目录自动监控」）



* 启用开关、**监控目录列表（可添加 / 删除多条，每条填绝对路径）**、扫描间隔（秒）；

* 状态行：`运行中 / 已停止` + 每个目录独立显示 `上次扫描 xx:xx / 发现新文件 N 个 / 最近触发任务 #N`；

* 提示文案：`放入该目录的文件将自动识别归档；待人工确认的文件会保留在原处，可在系统内审核`。

## 四、功能 B：盖章检测

### 4.1 检测原理（本地图像算法，零 AI token）

公章（合同 / 发票 / 结算单）以**红色圆形章**为主，用 cv2 做确定性检测：



```
图像 → 转 RGB

&#x20; → 红色掩膜：R > 120 且 (R-G) > 40 且 (R-B) > 40

&#x20; → 形态学闭运算去噪（核 3x3）

&#x20; → 找轮廓（findContours）

&#x20; → 逐个判定：

&#x20;     面积占比合理（章直径约占页面 3%\~15%）

&#x20;     圆形度 = 4π·面积 / 周长²  > 0.55

&#x20; → 输出：章数量 count、是否检测到 detected、置信度、各章中心/半径
```



* **彩色扫描件**：红章清晰，检出率高；

* **黑白扫描件**：红章变灰 → 检测不到 → 输出「疑似」（三态兜底，不误判 "无章"）；

* 单页多章（骑缝章 / 多个章）→ count 统计多个。

### 4.2 新服务：`backend/services/seal_detector.py`



```
@dataclass

class SealResult:

&#x20;   detected: bool      # 是否检测到章

&#x20;   count: int          # 章数量

&#x20;   confidence: float   # 0\~1

&#x20;   status: str         # "sealed" | "unsealed" | "suspect"

&#x20;   detail: list        # \[{"cx":..,"cy":..,"r":..}, ...]

def detect\_from\_image(image: PIL.Image, page\_w: int, page\_h: int) -> SealResult

def detect\_from\_file(path: Path) -> SealResult
```



* `detect_from_file` 按类型分发：


  * **图片**（jpg/png/bmp/webp…）：直接读图检测；

  * **PDF**：PyMuPDF 渲染**首页 + 末页**（盖章通常在落款页），逐页检测取最优；

  * Word / Excel / 其他：跳过，返回 `{"detected": False, "skip": True}`。

### 4.3 接入位置（processing\_service.\_handle\_file）

在 `classifier.analyze()` 之后追加一步（失败不影响主流程，try/except 包裹）：



```
if settings.SEAL\_DETECT\_ENABLED and file\_type in ("pdf", "jpg", "png", "jpeg", "bmp", "webp"):

&#x20;   seal = seal\_detector.detect\_from\_file(file\_path)

&#x20;   # 写入 document\_fields：

&#x20;   #   seal\_status   = sealed / unsealed / suspect

&#x20;   #   seal\_count    = N

&#x20;   #   seal\_confidence = 0.x
```

**结果展示**：



* 人工审核页 / 文档库字段区：显示 `盖章：已盖章 ×2` / `未盖章` / `疑似（建议人工确认）`；

* 可选增强（后续）：文档库 / 审核列表按 `未盖章` 筛选。

### 4.4 依赖声明



* 运行环境已有 numpy/opencv；为可复现，在 `requirements.txt` 补充声明 `numpy>=1.26`、`opencv-python-headless>=4.9`（cv2 5.0 兼容，headless 版本适合无 GUI 服务）。

## 五、风险与边界



| 风险                   | 应对                                                        |
| -------------------- | --------------------------------------------------------- |
| 监控目录误配（指向归档目录 / 回收站） | 启动校验拒绝 + 明确提示                                             |
| 自动触发整理消耗 token       | 触发后走现有「规则优先→OCR→模板→AI 兜底」链路，**识别策略不变**；监控只负责 "发现"，不降级审核门槛 |
| 黑白 / 模糊章检测不准         | 三态输出（已盖章 / 未盖章 /**疑似**），疑似不进自动归档判定，人工瞄一眼                  |
| 监控目录被删 / 无权限         | 状态栏报错、线程不崩溃，目录恢复后自动继续                                     |
| job 与扫描并发            | 复用 `_has_running()` 防止任务叠加                                |
| 大 PDF 渲染耗时           | 只渲染首页 + 末页；检测单页毫秒级                                        |

## 六、测试计划

**功能 A（folder\_watcher）**：



1. 启用监控 → 放入新文件 → 自动触发 job（job 表出现记录）

2. 无新文件 → 不触发（job 数不增）

3. 监控目录 = 归档目录 / 回收站 → 拒绝启动

4. 已有运行中 job → 不叠加触发

5. 目录删除 → 状态报错不崩溃 → 重建后恢复

6. 配置保存 → 线程动态启停（无需重启服务）

**功能 B（seal\_detector）**：



1. 合成图：纯色无章 → 未盖章

2. 合成图：红色圆形章 ×1 / ×2 → 检出数与 count 正确

3. 黑白化红章图 → suspect（不误判 sealed）

4. 真实样例：扫描合同（有章 / 无章）各一份人工核验

5. 图片 + PDF（首页 / 末页）路径均覆盖

6. 关闭开关 → 不执行检测

**回归**：全量 `pytest` 基线（当前 358+）全部通过，不新增 migration、不破坏老数据。
