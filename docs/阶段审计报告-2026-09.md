## 六、当前识别流程（以 `classifier.analyze` 代码实际逻辑为准）

```
文件进入
  ↓ 0. 文件名规则命中？───────────→ 置信度 0.99，直接归档（省 token 快通道）
  ↓
 1. 解析（PDF / Word / Excel / 图片）
  │  扫描件判定：平均每页文本 <50 字符 → 需要 OCR
  ↓
 2. OCR（RapidOCR 本地，零 token）
  │  + ocr_cleaner 二次清洗：数字纠错 / 日期统一 / 公司名模糊匹配
  ↓
 3. 规则引擎（54 条关键词规则）
  ↓
 4. 字段提取（多规则并行：正则 + 关键词 + 模板 + 文件名补全）
  │  带冲突检测（field_conflicts）
  ↓
 4.3 Excel 台账匹配（纯本地零 token）
  │  合同号 / 日期+船名 / 物料+数量 命中台账行
  │  → Excel 行字段覆盖 OCR 结果（source=EXCEL，权重 1.0）
  ↓
 4.6 格式样本匹配（纯本地零 token）──→ 命中 → 自动归档
  │  规则强命中（≥2 关键词）与样本冲突时信任规则（销售/采购版式修复）
  ↓
 4.5 识别模板匹配（字段齐全）──→ 命中 → 置信度 0.96，自动归档，跳过 AI
  ↓
 5. AI 兜底（仅当：AI 启用 且（无规则命中 或 规则置信度 < 0.85））
  │  AI 置信度 < 0.5 视为不可用，不覆盖规则结果
  ↓
 6. 置信度合成：规则 0.40 + 字段 0.20 + 关键词 0.15 + AI 0.25
  ↓
 7. 决策：≥0.85 自动归档 ｜ ≥0.60 待人工审核 ｜ 其余人工
  ↓
 8. 命名模板渲染（IF 条件 / 字段缺失自动跳过 / 日期格式化等自定义函数）
  → 归档（_001 防重名）→ operation_logs → 可撤销
```

**Token 控制结论**：文件名规则 → 规则 → 样本 → 模板 → Excel 台账均为**本地零 token**；AI 仅在"无规则命中且规则置信度不足"时兜底调用，且置信度 <0.5 丢弃——**AI 只在必要时候调用，符合"尽量少耗 token"原则**。

## 七、当前文件处理流程（以代码实际逻辑为准）

```
文件来源：inbox 目录 / 网页上传 / 邮箱附件 / 手动指定
  ↓ 创建 documents(status=pending) + processing_job
  ↓ 解析 → 识别（见第六节）
  ↓ 决策
  ├─ 自动归档 → 移动 + 重命名（safe_join 防越界、unique _001 防覆盖）
  │             → operation_logs（undo 可回滚）
  ├─ 待人工审核 → Review 页（预览 + 修改字段/分类/文件名 → 确认/跳过/批量）
  ├─ 重复文件 → duplicate_service 按 file_hash 检测
  └─ 失败 → status=failed，可 retry-failed
  ↓ 删除（单/批量）→ 回收站：documents 保留（status=recycled）、
  │  文件移动 data/recycle_bin/年/月/（document_id 前缀防冲突）→ 可恢复
  ↓ 备份：SQLite 一致性副本 + .env + 可选归档文档 → data/backups/ zip
```

**安全机制核验**：
- 路径越界：`safe_join` 全链路使用，越界抛 ValueError ✅
- 重名覆盖：`safe_filename` 非法字符清洗 + `unique_filename`/`build_unique_path`（_001 递增）✅
- 误删：删除一律走回收站，永久删除是唯一物理删除通道 ✅
- 撤销：undo_service 覆盖归档/移动/重命名/回收站恢复 ✅

## 九、审计结论

1. **V1.0 基础功能全部达标**：解析/OCR/识别/分类/重命名/归档/审核/日志/撤销/备份闭环，294 测试通过，文件安全机制无 P0 风险。
2. **V1.5 已部分落地**：回收站（V1.5-01/02/03）、整理预览、文件去重基础、AI 判断依据、高级规则（AND/OR）均已具备；待办为规则模拟器、自定义字段、系统健康中心细化。
3. **V2.0 业务档案时机成熟**：字段提取与 Excel 台账匹配已为"业务档案"打好数据底座，实现业务档案（合同↔结算单↔货权↔发票关联管理）仅需新增 2 表 + 聚合服务 + 前端档案页，是当前性价比最高的下一步。
4. **整体建议优先级**：① 改强访问密码（低风险高收益）→ ② V2.0 业务档案（用户核心诉求）→ ③ 邮箱接收实测收尾 → ④ 规则模拟器等 V1.5 收尾项。
