## 一、项目概况

| 项目 | 内容 |
|---|---|
| 定位 | Windows 本地运行的 AI 文档自动管理工具（本地智能文档整理 → 文档资产管理 → 业务档案管理） |
| 后端 | FastAPI + Uvicorn，SQLAlchemy 2.0（`Mapped`/`mapped_column` 强类型），Pydantic 2 |
| 数据库 | SQLite（WAL 模式），自研迁移机制（`backend/database.py`，SCHEMA_VERSION=4） |
| 前端 | Vue 3 + TypeScript + Vite + Element Plus + Pinia + vue-router |
| OCR | RapidOCR（ONNX 本地运行，PP-OCR 系模型），可切换 PaddleOCR |
| AI | OpenAI 兼容接口（当前配置：阿里云 DashScope，模型 `qwen-plus`） |
| 文件解析 | PyMuPDF（PDF）、python-docx（Word）、openpyxl（Excel）、Pillow（图片） |
| 测试 | pytest，当前 **358 个用例全部通过** |
| 启动方式 | `launcher.py` 一键启动 / `启动系统.bat` / `build_portable` 便携版 |
| 版本控制 | Git 本地仓库 + GitHub 远程（yunyun123111/smart-document-organizer） |

**核心识别原则**（代码实测确认）：
```
文件名规则 → 本地 OCR → 格式样本 → 识别模板 → 规则引擎 → AI 兜底 → 人工审核
```
AI 仅在规则、OCR、模板、样本均无法高置信度判定时调用，最大限度控制 token 消耗。

## 六、识别流程（代码实际逻辑）

```
文件进入
  ↓ 文件名规则命中？→ 是 → 直接自动归档（零 OCR/AI）
  ↓ 否
解析（PDF/Word/Excel/图片）
  ↓ 需 OCR → RapidOCR 本地识别 + 二次清洗（数字纠错/日期统一/公司名模糊匹配）
  ↓ 规则引擎（关键词 + 优先级 + 权重）
  ↓ 字段提取（正则 + 关键词 + 模板 + 文件名补全，多规则并行，冲突检测）
  ↓ Excel 台账匹配（合同号/船名+物料命中 → 用台账字段覆盖 OCR，零 token）
  ↓ 格式样本匹配（人工学习样本指纹）
  ↓ 识别模板匹配（同类型 + 关键字段齐全 → 自动归档）
  ↓ AI 兜底（仅当规则置信度 < 自动归档阈值时才调用）
  ↓ 置信度综合计算（规则+字段+关键词+AI 加权）
  ↓ 决策：自动归档 / 人工审核 / 拒绝
```

**token 控制实测**：文件名规则命中（如 SJWLXS 前缀）直接归档不调 AI；Excel 台账、样本、模板全部本地零 token；AI 仅在低置信度时兜底。

## 七、文件处理流程

```
上传（网页 / 邮箱附件 / 目录扫描）
  ↓ SHA256 判重（内容逐字节，重复直接拦截并提示来源文件名）
  ↓ 登记 pending → 收件箱
  ↓ 批量整理（多线程，任务进度原子计数）
  ↓ 识别 → 归档（安全命名 _001/_002，绝不覆盖）
  ↓ 归档后自动归集业务档案（合同号匹配 → 新建/挂载）
  ↓ 操作日志（可撤销）→ 文档库
  ↓ 删除 → 回收站（可恢复）→ 永久删除（二次确认）
```

安全机制（实测验证）：同名不覆盖、归档后源文件移出收件箱、路径越界防护（safe_join）、Windows 长路径兼容、只读目录明确报错、回收站恢复不覆盖已有文件。

## 十、已知问题与建议（按优先级）

### P1（重要）
1. **网易邮箱 IMAP 需携带 ID**：官方明确要求客户端连接时发送 IMAP ID（`store.id()`），否则拒绝登录。建议：在 `email_ingest.py` 的 IMAP 连接处补充 `imap_id()` 调用（Python `imaplib` 无原生接口，可用 `_simple_command('ID', ...)` 实现）。
